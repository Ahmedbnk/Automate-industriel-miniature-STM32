================================================================
           STM32 HAL (Hardware Abstraction Layer) GUIDE
================================================================

----------------------------------------------------------------
WHAT IS HAL?
----------------------------------------------------------------
HAL is ST's official middleware that hides register-level
complexity. You call HAL_GPIO_WritePin() instead of manually
toggling bits in the GPIOx->ODR register. It's portable across
STM32 families.

HAL is usually initialized by CubeMX, ST's code generator — it
generates the init boilerplate so you focus on your application.

Every peripheral has a HANDLE STRUCT (e.g. UART_HandleTypeDef
huart1). You fill it with config, pass it to HAL_XXX_Init(),
then use it in every subsequent call.

Core files in every project:
  - main.c                  your entry point
  - stm32f4xx_hal.h         HAL includes
  - stm32f4xx_hal_conf.h    enable/disable modules
  - SystemClock_Config()    clock setup (generated by CubeMX)
  - HAL_Init()              must be called first

Main loop skeleton:
------------------
    int main(void) {
      HAL_Init();                  // init HAL tick & NVIC
      SystemClock_Config();        // configure clocks
      MX_GPIO_Init();              // generated init functions
      MX_USART2_UART_Init();

      while (1) {
        // your application code
      }
    }


----------------------------------------------------------------
1. GPIO — General Purpose Input/Output
----------------------------------------------------------------
The simplest peripheral. Configure a pin as input or output,
then read or write it.

IMPORTANT: Always enable the GPIO port clock first — forgetting
this is the most common beginner mistake.

Init example:
-------------
    __HAL_RCC_GPIOA_CLK_ENABLE();

    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Pin   = GPIO_PIN_5;          // PA5 = Nucleo LED
    GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP; // push-pull output
    GPIO_InitStruct.Pull  = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

Output functions:
-----------------
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);    // HIGH
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);  // LOW
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);                 // toggle

Input functions:
----------------
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
    GPIO_InitStruct.Pull = GPIO_PULLUP;  // or GPIO_PULLDOWN

    GPIO_PinState state = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_0);
    if (state == GPIO_PIN_RESET) {
      // button pressed (active-low)
    }

Blink LED example:
------------------
    while (1) {
      HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
      HAL_Delay(500);  // 500 ms blocking delay
    }

2. UART — Serial Communication
----------------------------------------------------------------
UART is the go-to for debug output and PC communication.
HAL supports three modes:
  - Polling    (blocking, simplest — start here)
  - Interrupt  (non-blocking, callback-based)
  - DMA        (best for high throughput)

Init:
-----
    UART_HandleTypeDef huart2;

    huart2.Instance        = USART2;
    huart2.Init.BaudRate   = 115200;
    huart2.Init.WordLength = UART_WORDLENGTH_8B;
    huart2.Init.StopBits   = UART_STOPBITS_1;
    huart2.Init.Parity     = UART_PARITY_NONE;
    huart2.Init.Mode       = UART_MODE_TX_RX;
    HAL_UART_Init(&huart2);

Transmit (polling):
-------------------
    char msg[] = "Hello STM32!\r\n";
    HAL_UART_Transmit(&huart2, (uint8_t*)msg, strlen(msg), HAL_MAX_DELAY);

Receive (polling):
------------------
    uint8_t rxBuf[10];
    HAL_UART_Receive(&huart2, rxBuf, sizeof(rxBuf), 1000); // 1000ms timeout

printf() redirect tip:
----------------------
Override __io_putchar() to redirect printf() to UART:

    int __io_putchar(int ch) {
      HAL_UART_Transmit(&huart2, (uint8_t*)&ch, 1, HAL_MAX_DELAY);
      return ch;
    }

3. TIMERS — Timing & PWM
----------------------------------------------------------------
STM32 timers are very versatile: basic delay, periodic
interrupt, PWM output, input capture.

Key formula:
    Fclk / (PSC+1) / (ARR+1) = overflow frequency

Periodic interrupt (1 Hz at 84 MHz clock):
-------------------------------------------
    TIM_HandleTypeDef htim2;
    htim2.Instance         = TIM2;
    htim2.Init.Prescaler   = 8399;   // 84 MHz / 8400 = 10 kHz
    htim2.Init.Period      = 9999;   // 10 kHz / 10000 = 1 Hz
    htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
    HAL_TIM_Base_Init(&htim2);

    HAL_TIM_Base_Start_IT(&htim2);  // start in interrupt mode

    // Callback — called every 1 second
    void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
      if (htim == &htim2) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
      }
    }

PWM output:
-----------
    TIM_OC_InitTypeDef sConfig = {0};
    sConfig.OCMode     = TIM_OCMODE_PWM1;
    sConfig.Pulse      = 4999;  // 50% duty cycle (ARR = 9999)
    sConfig.OCPolarity = TIM_OCPOLARITY_HIGH;
    HAL_TIM_PWM_ConfigChannel(&htim2, &sConfig, TIM_CHANNEL_1);

    HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);

    // Change duty cycle at runtime:
    __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, newDuty);

4. I2C — Two-Wire Bus (SDA + SCL)
----------------------------------------------------------------
Used for sensors (MPU6050, BME280), OLED displays, EEPROMs.
STM32 is usually the master. Each device has a 7-bit address.

IMPORTANT: HAL requires the address left-shifted by 1:
    use (0x68 << 1), not 0x68

Init:
-----
    I2C_HandleTypeDef hi2c1;
    hi2c1.Instance            = I2C1;
    hi2c1.Init.ClockSpeed     = 100000;  // 100 kHz standard mode
    hi2c1.Init.DutyCycle      = I2C_DUTYCYCLE_2;
    hi2c1.Init.AddressingMode = I2C_ADDRESSINGMODE_7BIT;
    HAL_I2C_Init(&hi2c1);

Write to device:
----------------
    uint8_t data[2];
    data[0] = 0x6B;  // register address
    data[1] = 0x00;  // value to write
    HAL_I2C_Master_Transmit(&hi2c1, 0x68 << 1, data, 2, HAL_MAX_DELAY);

Read from device:
-----------------
    uint8_t reg = 0x3B;
    uint8_t buf[6];
    HAL_I2C_Master_Transmit(&hi2c1, 0x68<<1, &reg, 1, 100);
    HAL_I2C_Master_Receive(&hi2c1, 0x68<<1, buf, 6, 100);

Shortcut for register-based sensors:
-------------------------------------
    // Reads 6 bytes from register 0x3B in one call
    HAL_I2C_Mem_Read(&hi2c1, 0x68<<1, 0x3B,
                     I2C_MEMADD_SIZE_8BIT, buf, 6, 100);

5. SPI — Four-Wire Full-Duplex Bus
----------------------------------------------------------------
Faster than I2C. Uses MOSI, MISO, SCK, and a CS (chip select)
pin per device. CS is a GPIO pin you toggle manually — HAL
does NOT manage it automatically.

Init:
-----
    SPI_HandleTypeDef hspi1;
    hspi1.Instance               = SPI1;
    hspi1.Init.Mode              = SPI_MODE_MASTER;
    hspi1.Init.Direction         = SPI_DIRECTION_2LINES;
    hspi1.Init.DataSize          = SPI_DATASIZE_8BIT;
    hspi1.Init.CLKPolarity       = SPI_POLARITY_LOW;
    hspi1.Init.CLKPhase          = SPI_PHASE_1EDGE;
    hspi1.Init.NSS               = SPI_NSS_SOFT;
    hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_16;
    HAL_SPI_Init(&hspi1);

Transmit only:
--------------
    uint8_t txBuf[] = {0x02, 0xAB};

    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_RESET); // CS low
    HAL_SPI_Transmit(&hspi1, txBuf, 2, 100);
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_SET);   // CS high

TransmitReceive (full-duplex):
------------------------------
    uint8_t tx[] = {0x80 | 0x28, 0x00};
    uint8_t rx[2];

    HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_RESET);
    HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);
    HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_SET);

6. ADC — Analog to Digital Conversion
----------------------------------------------------------------
Converts analog voltage (0–3.3V) to a digital value.
Default resolution is 12-bit: values from 0 to 4095.

Init & channel config:
----------------------
    ADC_HandleTypeDef hadc1;
    hadc1.Instance                = ADC1;
    hadc1.Init.Resolution         = ADC_RESOLUTION_12B;
    hadc1.Init.ScanConvMode       = DISABLE;
    hadc1.Init.ContinuousConvMode = DISABLE;
    hadc1.Init.ExternalTrigConv   = ADC_SOFTWARE_START;
    HAL_ADC_Init(&hadc1);

    ADC_ChannelConfTypeDef sConfig = {0};
    sConfig.Channel      = ADC_CHANNEL_0;  // PA0
    sConfig.Rank         = 1;
    sConfig.SamplingTime = ADC_SAMPLETIME_3CYCLES;
    HAL_ADC_ConfigChannel(&hadc1, &sConfig);

Read value (polling):
---------------------
    HAL_ADC_Start(&hadc1);
    HAL_ADC_PollForConversion(&hadc1, HAL_MAX_DELAY);
    uint32_t raw = HAL_ADC_GetValue(&hadc1);
    HAL_ADC_Stop(&hadc1);

    // Convert to voltage (3.3V reference, 12-bit)
    float voltage = raw * 3.3f / 4095.0f;

Pro tip — use DMA for continuous sampling:
------------------------------------------
Polling ADC in a loop burns CPU cycles. For high-speed or
multi-channel sampling, configure ADC in continuous mode with
DMA — the hardware fills a buffer automatically while your
code does other work.


----------------------------------------------------------------
RECOMMENDED LEARNING ORDER
----------------------------------------------------------------
  1. GPIO          — blink an LED, read a button
  2. UART          — set up printf() for debug output early
  3. Timers        — periodic interrupts, then PWM
  4. I2C           — read a sensor (MPU6050, BME280, etc.)
  5. SPI           — faster peripherals (displays, IMUs)
  6. ADC           — analog sensors, potentiometers
  7. DMA           — offload data transfers from the CPU
  8. RTOS (FreeRTOS) — multitasking with HAL

----------------------------------------------------------------
TIPS
----------------------------------------------------------------
  - Use CubeMX to generate all init boilerplate — it handles
    prescaler math, pin mapping, and clock config for you.
  - Always write your code inside /* USER CODE BEGIN/END */
    blocks so CubeMX doesn't overwrite it on regeneration.
  - HAL_Delay() is a blocking delay using the SysTick timer.
    Avoid it in production; use timers or RTOS delays instead.
  - HAL_MAX_DELAY means the call will wait forever — fine for
    learning, replace with real timeouts in production code.
  - Enable UART first thing and redirect printf() — being able
    to print debug values saves enormous amounts of time.
